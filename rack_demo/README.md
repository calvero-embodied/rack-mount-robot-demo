# ラック搭載支援デモ

Gazebo Ignition + ROS 2 Humble + CRANE+ V2に、昇降台と支持・把持治具を追加した縮小デモです。
起動時から左に1U、右に2Uの機器があり、質問への回答に応じて取り上げ、ラックへ運びます。

[プロジェクトの概要へ戻る](../README.md)

## 起動前の確認

この手順は、**講義環境のコンテナ `pai_ros2` が作成済み**の方向けです。Dockerをインストールしただけの環境では実行できません。

- コンテナ内にROS 2 Humble、Gazebo Ignition 6、CRANE+関連パッケージが導入済みであること。
- `/home/ubuntu/airobot_ws/install/setup.bash` が存在すること。
- コンテナのデスクトップが `DISPLAY=:0` で使用できること。
- ブラウザ表示を使う場合は、コンテナのデスクトップへ接続できること。既存の講義環境では `http://localhost:6080` を使用します。

コンテナを確認するコマンドは次のとおりです。

```powershell
docker ps -a --filter name=pai_ros2
```

対象コンテナが表示されない場合は、先に講義の手順で環境を構築してください。このリポジトリにはコンテナを新規構築するDockerfileは含まれていません。

## 1. コードを取得する

初めて取得する場合は、PowerShellで次を実行します。

```powershell
git clone https://github.com/calvero-embodied/rack-mount-robot-demo.git
cd rack-mount-robot-demo
```

すでに取得済みの場合は、既存のプロジェクトのルートへ移動してください。**`rack_demo` フォルダが見える場所**で、以降のコマンドを実行します。

## 2. Gazeboを起動する（PowerShell A）

操作プログラムが開いている場合は、先に `q` で終了してください。次の停止・起動操作は現在のシミュレーションを終了し、機器を初期配置へ戻します。

```powershell
docker start pai_ros2
docker cp ./rack_demo/. pai_ros2:/home/ubuntu/rack_demo/
docker exec pai_ros2 pip install -r /home/ubuntu/rack_demo/requirements_collision.txt
docker exec pai_ros2 python3 /home/ubuntu/rack_demo/stop_simulation.py
docker exec -it -e DISPLAY=:0 pai_ros2 bash /home/ubuntu/rack_demo/start_demo.sh
```

http://localhost:6080 を開くと、ラックと左右の機器が指示前から配置されています。
左・右はロボットが正面のラックを向いたときの向きです。
初期機器は左右90度・中心から21cmの受台に置かれます。
新しい起動ファイルが昇降軸のコントローラも設定するため、旧シーンからは再起動が必要です。
当たり判定や治具形状の変更も、Gazeboの再起動で反映されます。

**PowerShell Aは開いたままにしてください。** 起動処理が終わり、「左: 1U / 右: 2U。機器とラックを初期配置しました。」と表示されてから操作を始めます。

## 3. 操作を開始する（PowerShell B）

別のPowerShellを開き、次を実行します。

```powershell
docker exec -it pai_ros2 bash /home/ubuntu/rack_demo/run_demo.sh
```

### 入力と人が担当する操作

1. 「どの機器ですか？」に `1u` または `2u` と回答します。
2. 「どこに設置しますか？」に `上段` または `下段` と回答します。英語の `upper` / `lower` でも構いません。
3. 設置済み機器との重なりと在庫を確認します。重なる場合は警告して動かず、質問へ戻ります。
4. 左の1U／右の2Uへ旋回し、支持台を機器の下へ差し込んで持ち上げ、把持状態にします。
5. 指定した高さへ運搬・保持します。
6. 人がねじ止めを終えた想定で **Enter** を押すと、ラックへ固定して治具を退避します。
7. 再び機器と位置を質問します。そのまま2台目を設置できます。終了は `q` です。

例：1Uを下段に設置 → 2Uを下段に指示すると衝突警告 → 上段に指示し直すと2Uを設置。
機器は1U・2U各1台です。使用済みの機器は再選択しても取りに行きません。

最初に試す場合の入力例です。`Enter` は文字として入力せず、キーを押してください。

```text
どの機器ですか？ [1u / 2u] > 1u
どこに設置しますか？ [上段 / 下段] > lower
（ロボットが機器を下段へ運び、保持するまで待つ）
ねじ止め完了後にEnter > Enterキーを押す
```

機器・設置先の質問で `q` を入力すると、操作プログラムを終了します。Gazeboも閉じる場合は、PowerShell AでCtrl+Cを押します。

## 閉じた後に再開するには

| 閉じたもの | 再開方法 |
|---|---|
| ブラウザだけ | `http://localhost:6080` を開き直す |
| 操作プログラムだけ | Gazeboを起動したまま、手順3のコマンドを再実行する |
| Gazebo・起動用PowerShell | 操作プログラムも終了し、手順2から起動し直す |
| Dockerコンテナ | Dockerを起動し、手順2から実行する |

操作プログラムだけを終了した場合、同じGazebo内では設置済み機器が残ります。Gazeboを起動し直した場合は、左右の初期配置から再開します。

## よくあるエラー

| 表示・症状 | 確認と対処 |
|---|---|
| `/world/default/pose/info` の受信が10秒でタイムアウトする | Gazeboが起動しているか確認する。閉じている場合は手順2で起動し、初期配置の完了を待つ |
| `Another rack session is already running.` | 起動直後なら初期配置の完了を待つ。別の操作プログラムが開いている場合は `q` で終了する |
| `No such container: pai_ros2` | 必要な講義コンテナが存在しないため、講義の環境構築を先に行う |
| `ModuleNotFoundError` で `fcl` / `trimesh` が見つからない | 手順2の `pip install -r .../requirements_collision.txt` を実行する |
| ブラウザに接続できない | Dockerコンテナと、講義環境のデスクトップ接続・ポート設定を確認する |
| 衝突する経路のため停止した | 警告に出た対象を確認する。手動でモデルを動かした場合などは、シーンを確認してから初期化または再起動する |

## 高さ・把持・固定の再現範囲

- ラック高さ：約48cm。ハンドが上枠に当たらない高さにしています。支持台中心は上段33cm、下段3cm。機器底面は机から約33.2cm／3.2cmです。
- 1U：12 × 19 × 1.8cm、50g。青い前面・ポート1列。
- 2U：12 × 19 × 3.6cm、100g。茶色の前面・ポート2列。
- 機器は左右の受台上に最初から存在します。指示後の取り上げ・運搬中に生成し直したり座標を追従させたりしません。
- 治具は中央を支える7cm四方の支持パッドです。取付ブラケットはハンドの側方を迂回し、パッドへの接続部は下面に配置しています。下部横桟は縮小モデルで厚さ6mmとしています。
- 最初の持上げは支持台と機器の物理接触で実行します。その後、GazeboのDetachableJointによる固定拘束を把持として使用します。
- ねじ止め完了は機器とラックの固定ジョイントで表します。ねじ回転や実際の締結力・指の摩擦把持は再現しません。
- 元のアーム・ハンドの衝突メッシュを保持し、治具の6部品すべてに表示と一致する衝突ボックスを設定しています。自己衝突も有効です。固定された取付面や隣接関節の接続部分は通常のロボットモデルと同様、検査対象から除きます。ハンドと治具の間は検査します。
- 動作指令の送信前にFCLで関節補間中の姿勢も検査します。関節刻みは最大0.01rad、昇降刻みは最大1mm、非接触部の最小許容距離は2mmです。ハンドの開閉中も検査します。衝突する経路は送信せず停止します。
- 機器を載せるパッド面、持上げ開始時の機器と受台、ベースと机の取付面は意図した接触です。ハンドやブラケットが機器を貫通することは許可していません。パッドと機器の支持接触は数値誤差1mmまでとしています。
- 設置先が使用済みの場合は、登録済み機器の実位置と寸法によるAABB判定で、取りに行く前に拒否します。経路検査はラック・受台・機器・机を対象とします。未知の障害物の認識や、動く障害物への回避経路の再計画は含みません。
- 実寸19インチ規格や実機の可搬性能を検証するモデルではありません。
- **AIによる自然言語解釈はまだ未実装です。** 現段階は回答を選択値として受け取る処理で、次にAIを接続するための動作基盤です。

## 記録と初期化

`/home/ubuntu/rack_demo/session_state.json` に在庫・設置済み位置を保存します。
操作プログラムを終了して再実行しても、同じGazebo内では設置済み機器が残ります。
Gazeboを起動し直すと機器を初期配置し、設置記録も新しくなります。

ログは `session_log.json`、連続検証結果は `session_verification.json` です。
機器のエンティティID、実位置、関節誤差、衝突拒否、設置台数を記録します。
`path_checked` には、その指令内の検査で得た最小距離を記録します。
`contact_audit.json` はGazebo起動後の接触センサの累積集計です。支持パッドと機器の接触は正常です。
`collision_geometry_verification.json` は、ハンドの開閉と、故意に重ねた機器・治具を拒否する検証結果です。
`collision_physics_verification.json` は別の隔離シーンでハンドと機器／治具を故意に接触させ、Gazeboの物理接触も発生することを確認した結果です。
`collision_paths_verification.json` は1U・2Uと上段・下段を、設置順序も入れ替えて検査した8経路の結果です。
以前の動作確認結果は `validation/` にあります。衝突形状の変更前の記録とは区別してください。
衝突を有効にした版の記録は `validation/collision_enabled/` です。1U下段→同段への2U拒否（動作0回）→2U上段をGazeboで完了し、ハンド・ブラケットの意図しない接触がないことを確認しました。
各機能の動作確認であり、成功率や実機安全性の統計評価ではありません。

自動操作での検証例（ねじ止め完了も自動）：

```powershell
docker exec -it pai_ros2 bash /home/ubuntu/rack_demo/run_demo.sh --sequence 1u:lower,2u:lower,2u:upper
```

初期化して左右の機器を補充する場合（設置済みの機器を取り除きます）：
対話プログラムは先に `q` で終了してください。

```powershell
docker exec -it pai_ros2 bash /home/ubuntu/rack_demo/run_demo.sh --reset --prepare
```

動作中は別の操作プログラムや講義のテレオペを起動しないでください。同時操作はロックでも拒否します。
Gazeboは再生状態で使用します。

## ファイル

- `rack_session.py`：対話・連続設置・動作前チェック・運搬。
- `session_scene.py`：初期機器・受台・在庫・把持／固定ジョイント。
- `demo_scene.py`：昇降台付きロボット、ラック、機器、逆運動学。
- `collision_guard.py`：FCLによる自己衝突・環境・運搬機器・関節補間経路の検査。
- `simulation_files.py` / `contact_monitor.cc`：衝突形状を保持したSDF生成・接触センサ・接触集計。
- `rack_demo.launch.py`：専用シーンの起動と初期配置。
- `control_demo.py` / `setup_scene.py`：共通処理と旧デモの実装。通常は直接実行しません。

講義のインストール済みファイルは変更しません。
